# furigana 只在答案面渲染

**背景。** 讀音既然行內寫好（ADR-0012），Renderer 想在哪裡顯示都行。但有一大類日文卡片存在的目的正是測驗*讀出漢字*：正面是 勉強，要回想的東西是 べんきょう。若在問題面把讀音顯示在漢字上方，就等於把答案交給學習者，讓卡片失效。然而也有些卡片把讀音當輔助而非答案（一個要翻譯的長句），這時把讀音藏起來對誰都沒好處。

**決策。** 讀音只在答案面渲染。在問題面，帶標記的文字以 base-only 呈現（只顯示漢字，讀音與分隔空白都去掉，即 Anki 的 `kanji:` 模式）；在答案面則以堆疊呈現，讀音在 base 上方（Anki 的 `furigana:` 模式）。這對兩個欄位都成立，所以含漢字的 `back` 在揭示後也會得到 furigana。曾考慮並延後了一個 config 開關（`answer-only | always | never`）：它會為了一個尚無 dogfooding 要求過的偏好，多加一個 config key 與一個要驗證的值。之後要把預設行為變成可設定，不需要重開這個決策。

**後果。** 一張測驗讀音的卡片仍是誠實的測驗，與 ADR-0002 拒絕讓表面搶先透露複習所要衡量之物的原則一致，只是這裡套用在揭示（reveal）邊界而非排程。想在回想時就看到讀音的輔助型卡片作者，在這個版本拿不到那個行為；如果這個需求在 dogfooding 冒出來，那個被延後的 config 開關就是答案，而這筆紀錄就是那個張力被暫存的地方。問題面與答案面現在對同一欄位跑不同的 render 模式，furigana module 必須把它暴露成兩個進入點。規格：[`docs/specs/furigana-ruby-display.md`](../../specs/zh-TW/furigana-ruby-display.md)。
